# Internal Cargo execution and actual manager review

The approved standalone workflow now has an INTERNAL-only server provider around the existing receipt and trip engine. It resolves the saved request, the exact immutable manifest and its `fleetops` ownership, the current employee role and the assigned driver. It does not accept origin or authority from the request body. The existing simulated factory remains restricted to test/development and refuses production; PMS/POS/SCM execution and machine integration endpoints remain unavailable.

The first authorized read creates the execution from the saved manifest. Pickup and delivery observations retain the existing immutable handover, exact quantities, signature payload, evidence ownership and submission identity. INTERNAL pickup always waits for explicit manager release, including a clean count. A separate securement review requires all load safety confirmations and binds the actual driver/vehicle. Receiving can be reviewed after its receipt is saved; explicit manager acceptance can accept a recorded delivery difference while preserving the original shortage figures. Typed receiver references and signatures alone do not grant authority.

`reviewInternalCargo` accepts one stable submission UUID, current receipt and execution version, SOURCE/SECUREMENT/RECEIVER kind, the matching action, reason, reviewed evidence IDs and securement confirmations where needed. Every attached photo must be included before an accepting decision. Up to 2,500 unique IDs cover the receipt contract's 500 lines with five photos each. The authenticated Fleet Manager/admin/super_admin identity is saved; dispatchers cannot decide.

Reviews, source decisions, clearances, required audit and original response commit atomically. Exact retry returns the saved response after authorization; changed actor/content conflicts. Recounts invalidate old receipt-bound authority. Later views resolve current saved reviews rather than rewriting original responses. Assignment changes invalidate securement. Existing holds from the first pickup prevent cancellation/reassignment without a separate custody disposition. INTERNAL event history remains local and creates no partner outbox work.

Migration `170_internal_cargo_reviews.sql` adds the private append-only review table, extends only the relevant source/command constraints and permits explicit INTERNAL_PRESERVE evidence metadata. SQL binds manager identity, receipt/stage/hash/version, assignment, evidence and source/clearance records. Deferred guards require an audited immutable response for every review and a manager review for every INTERNAL decision/clearance. The table enables RLS and revokes all exposed-role privileges, including TRUNCATE. Parent integration applied it through `db:up` and refreshed generated `schema.sql` through `db:dump`. Fresh status is170 applied/0 pending/0 changed; the live contract checks93 relations with0 violations. The applied migration is frozen.
