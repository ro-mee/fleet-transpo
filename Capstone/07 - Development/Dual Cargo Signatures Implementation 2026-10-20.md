## Receipt and signature contract

Each new pickup or delivery receipt requires a version 1 `handover` in its existing private immutable JSON payload. It includes the releasing/receiving person's name and role/department, the `CARGO_HANDOVER_V1` acknowledgment, device capture time, bounded numeric drawing and optional location. The parent receipt supplies exact trip, manifest revision, stage, per-item quantities/condition, authenticated recording employee/driver, submission identity and server `received_at`. No independent signature table, migration, duplicate handover endpoint or generated schema edit was necessary.

The platform-neutral validator rejects blank/tap-only drawings, nonfinite/nonnumeric/off-canvas points, arbitrary markup, unknown fields, nonplain objects and sparse/decorated arrays. Drawing bounds are 600 by 240, at most 64 strokes and 2,048 points. Name and role/department are trimmed and bounded at 160/120 characters. Location, when actually obtained, has bounded latitude/longitude and accuracy; its observation must be within five minutes before or one minute after signature capture. Historical validation is deterministic. New commands reject device timestamps over five minutes ahead of server time; old signed offline drafts are not silently expired.

History parsing accepts older unsigned receipts and exact archived command responses. Replay lookup precedes the new-handover requirement; exact retries return the original immutable response and changed drawing/content conflicts. Unsigned current receipts cannot grant departure/completion or new Fleet clearance. Recounts need a fresh signature and retain earlier signed observations. Signatures and incident IDs do not replace separate source decisions, Fleet securement or server-resolved receiving authority.

## Driver application

Existing cargo item-count review opens the signature modal for a new observation. Pickup asks for releasing staff name/role; delivery asks for receiving staff name/department. The person explicitly acknowledges the reviewed quantities and condition. Cancel keeps counts and sends nothing; clear discards the drawing and acknowledgment. The submitted snapshot is frozen. Changes to counts, issues, stage, manifest, account/session, assignment, trip status/type or connection invalidate or refuse stale confirmation.

The drawing surface uses the installed WebView with a fixed canvas and bounded numeric bridge messages; no package or native configuration was added. Its document disallows network/resources and file access. All navigation except `about:blank` is refused before the installed adapter can invoke external linking. The deliberately broad WebView origin whitelist routes every navigation through this refusal callback; a narrow whitelist would instead let the adapter open rejected schemes externally.

Location is optional and honestly unavailable on denial, invalid/stale fix, provider failure or bounded timeout. A late permission reply after cancellation/timeout cannot start another GPS request. Late results from an already-started native request are ignored. Unsent signer data remains in memory and is filtered out of form autosaves. Deliberately submitted immutable cargo drafts retain their original signature for exact retry. Device-saved, Fleet-saved and partner-acknowledged states stay distinct.

The modal submits observations only. Existing Map/Home transition guards and Passenger/Cargo odometer capture remain authoritative. No signature action completes a trip or changes fuel logging.

The existing cargo permission matrix, live authentication, assigned-driver ownership and independently approved staff authority still apply. The two stage regions show validated fixed SVG paths, signer and role/department, exact receipt reference and manifest revision, item counts/condition/issues, device/observation/server times and optional GPS accuracy. Item names and units are borrowed only from an exactly matching manifest kind/ID/revision/hash. Older or mismatched descriptions cannot overwrite what was signed. Narrow layouts stack the two regions. Raw manifest hashes and technical manifest UUID/type details stay out of the operational display.

Private details live only in component memory, scoped to trip and current employee/session/role. Hide, account/trip changes and unmount clear or abort them. Revoked authorization discards previous details; transient refresh errors keep previously loaded facts with an explicit retry message. Historical unsigned records are labeled honestly.

Partner outbox payloads use an explicitly public receipt schema that rejects private handover data. Redaction occurs before event hashing and persistence, including stored-input comparisons. Independent review found and reproduced a separate machine source-decision HTTP response leak; the HTTP response is now projected through the private-field filter on both first response and exact retry, while internal immutable audit/command snapshots remain unchanged.
