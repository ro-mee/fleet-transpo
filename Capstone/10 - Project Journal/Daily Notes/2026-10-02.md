## Safety review findings

- `mobile/components/TomTomMap.js` still inserts booking text into executable
  WebView script and HTML contexts without escaping for each context. Popup
  labels are HTML-escaped but then placed inside a single-quoted JS literal;
  trip addresses do not neutralize `</script>`, and radar marker titles reach
  `innerHTML`. This can break the map script and may allow script execution
  from attacker-controlled reservation text.
- `mobile/lib/gps-odometer.js` leaves its foreground anchor unchanged after a
  stale-gap rejection. Further fixes then remain beyond the five-minute limit
  from that same anchor. `mobile/lib/background-tracking.js` separately resets
  its anchor on every fix, so background and foreground odometer behavior
  differs.
- The working copy of the October 1 journal contains merge-conflict markers;
  its staged version differs from the working copy.

## Decisions made

Created [[Mobile Map WebView and GPS Odometer Safety Implementation Plan]] for
the two mobile defects. The proposed WebView fix uses an inline-script-safe
serializer and text-only marker labels. The proposed GPS rule drops distance
across an unobserved gap, confirms a new anchor with a subsequent plausible
fix, and leaves short-interval outliers untrusted. This is a plan only; no application code or

## Implementation follow-up

Implemented both planned code fixes. The WebView now serializes script data,
escapes HTML/CSS contexts, validates coordinate/radius values, removes unused
raw trip objects from radar payloads, and renders marker labels as text. The
odometer now requires a second plausible fix to confirm a new anchor after a
long gap; background AsyncStorage persists the same state and resets it at
trip/leg/app-state boundaries.
