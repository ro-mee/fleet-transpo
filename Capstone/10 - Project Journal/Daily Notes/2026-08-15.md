## What I learned

- Fail-open vs fail-closed is a caller contract: `driverBlockReason` is fail-open when the caller never loaded schedule context (`!ctx?.schedules`), fail-closed only when context was loaded and the map is empty. Same helper, two behaviors — deliberate.
- `TIME` columns return as `"HH:MM:SS"` strings; lexicographic comparison is safe.
- Server TZ is Asia/Manila — schedule day-of-week must use local getters, consistent with `toCalendarDay`.
- A JSX esbuild check needs `--loader:.js=jsx`.

## Decisions made

- Fleet Manager (not admin) is the schedule writer; admin observes. Write gated `system_admin` + `fleet_manager`.
- No schedule row = **not assignable** (fail-closed). Approved leave only blocks; Pending doesn't.
- Rest day stored as 00:00–00:00. Break rule is half-open: blocks only when it actually overlaps the trip window.
- Backfill hours are a neutral default, **not** policy — fleet manager sets real shifts via the editor.
- Attendance/check-in remains deferred (per user).
