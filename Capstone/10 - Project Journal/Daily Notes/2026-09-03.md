# 2026-09-03

## What I worked on

### Mobile driver app — sync, tracking, navigation, traffic (all uncommitted)

- **Login 429 loop fixed** (`mobile/lib/api.js`, `mobile/lib/sync.js`): auth requests are never queued for replay — a queued login resurfacing minutes later just hammered the rate limiter. The sync loop now drops any stale auth request already in the queue and classifies failures correctly: network errors, 429, and 5xx stay queued (transient); everything else is a permanent drop, with incident reports quarantined instead of silently lost.
- **Loading buttons no longer expand** (`mobile/components/ui.js`): all four button variants overlay the spinner on the label with `absoluteFill` and fade the text out, so the button keeps its size while confirming. Pattern copied from the existing `CriticalTonalButton`.
- **Single GPS poster** (`mobile/lib/tracking.js`, mounted in `mobile/app/(app)/_layout.js`): one `useActiveTripGpsPoster` owns posting location every 30 s to the active trip. Previously each visited tab ran its own poster (up to 3 duplicate rows per interval) and any pushed screen stopped posting entirely. Screens now use the watch-only `useTripTracking` for display data; poster status (last-sent/error) is shared through a module-level pub/sub.
- **Tab bar no longer under the Android 3-button nav bar** (`mobile/app/(app)/(tabs)/_layout.js`): SDK 54 forces edge-to-edge and the custom `tabBarStyle` overrides React Navigation's automatic safe-area padding, so the bottom inset is added manually via `useSafeAreaInsets`.
- **Live navigation accuracy** (`mobile/components/TomTomMap.js`, `mobile/app/(app)/(tabs)/map.js`) — 7 fixes:
  - `MAP_READY` is dispatched even without an `onRouteData` handler, so the idle map no longer sits under the loading overlay forever.
  - Compass updates only apply on a ≥5° change — no more re-render/injection storms while parked.
  - Follow mode glides: `easeTo` (2.8 s) on every position update instead of a 800 ms jump every ~200 m of drift.
  - Route is recalculated every 2 min while moving (off the reroute path), so ETA/distance/traffic refresh and `ROUTE_CALCULATED` reaches the bottom sheet.
  - Reroute requires 2 consecutive >50 m off-route fixes, and a failed windowed snap retries against the full route before declaring off-route.
  - Recalculation removes the old traffic badges and alt-route layer before redrawing.
  - Initial routing failure shows "Route unavailable" instead of a permanent "Calculating route...".
- **Traffic minutes were dead code** (`mobile/components/TomTomMap.js`): Routing API v1 TRAFFIC sections have no `delayInSeconds` field, so `Math.ceil((undefined || 0) / 60)` was always 0 and the "🚗 X min" badges never rendered. Badges now show a length-weighted share of the route-level `summary.trafficDelayInSeconds` (the only real number the API gives), and sections are read from the documented `response.routes[n].sections` with the geojson-properties copy kept as fallback. Severity colors fixed: red only for `magnitudeOfDelay >= 3` / `ROAD_CLOSED`, yellow otherwise (magnitude 0 "Unknown" was previously painted red).

## What I learned

- A queued "retry everything" offline sync is wrong for interactive auth paths — replaying a login minutes later is never what the user wanted.
- React Navigation tab screens stay mounted after being visited; any per-screen side effect (like GPS posting) must live above the navigator or it multiplies.
- Expo SDK 54 forces Android edge-to-edge; any custom `tabBarStyle` silently discards the automatic safe-area padding.
- TomTom Routing API v1 gives per-section severity (`magnitudeOfDelay`, `simpleCategory`) but no per-section delay — only the route-level `trafficDelayInSeconds`. Per-segment minute badges have to be derived by splitting that total.

## Decisions made

- Auth requests never enter the offline queue; permanent-failure incident reports are quarantined, not dropped.
- One global GPS poster owned by the `(app)` layout; screens only watch for display.
- Traffic badge minutes are a length-weighted split of the real route-level delay (marked with a `ponytail:` comment) — good enough until a per-section delay source is worth integrating.
- Trip-detail overview map stays traffic-free: it's a static preview, not live navigation.
