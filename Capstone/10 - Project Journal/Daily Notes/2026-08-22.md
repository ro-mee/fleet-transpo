# 2026-08-22

## What I worked on

### Security and quality gates — committed

Commit `1fae72c` (`fix: harden security and quality gates`) established a repeatable CI/security baseline:

- Added GitHub CI for `npm ci`, lint, all tests, migration validation, and the production build.
- Added `db:check`; migration discovery now rejects malformed filenames and any new duplicate version while preserving the known historical duplicates.
- Blocked an ordinary admin from creating a `system_admin` account.
- Stopped unexpected server errors from returning internal error messages to clients.
- Restricted API CORS to `NEXT_PUBLIC_APP_URL`; invalid origins now receive `403`.
- Hardened vehicle-image uploads: fleet-role authorization, numeric vehicle validation, 5 MB limit, JPEG/PNG/WebP signature checks, existence check, and storage cleanup when the DB update fails.
- Added focused security-boundary and upload-validation tests.
- Fixed the missing mobile history router and gave `TomTomMap` an explicit display name.

An uncommitted CSP follow-up now permits `unsafe-eval` only in development for React/Turbopack HMR while keeping production stricter.

### Mobile fuel receipt scanner — committed

Commit `3b5dd94` (`feat(mobile): streamline Gemini fuel receipt scanning`) rebuilt the mobile refuel capture path:

- The center Scan action in the bottom navigation now opens the receipt camera immediately through `scan=1`; it no longer stops at the method-selection screen.
- The embedded `CameraView` captures, previews, crops, resizes, and compresses the receipt before upload. `receipt-crop.js` maps the visible guide to the captured image coordinates.
- The receipt is uploaded first, then the authenticated server fetches the driver-owned signed URL and sends the image to Gemini.
- Gemini uses structured JSON output and the fast `gemini-3.1-flash-lite` model with a 12-second server timeout.
- Extracted fields are fuel brand, refuel date, liters, price per liter, and final amount paid. The prompt handles Petron table columns and discounted Skyewin/Shell totals.
- Station names are normalized to the fuel brand: Petron receipts become `PETRON`; Shell and Skyewin Prime Resources receipts become `SHELL`; dealer/operator names do not overwrite the brand.
- Local ML Kit OCR and deterministic receipt parsing were removed. If Gemini is unavailable, the uploaded receipt remains attached and the driver can complete missing fields manually.
- Odometer was removed from the form and Gemini schema. The mobile fuel API now records the assigned vehicle's latest server-side mileage automatically.
- The misleading fuel-gauge card was removed from the refuel screen.
- Receipt upload recovery and retry states prevent a captured photo from being lost when scanning or upload fails.
- Expo camera/image-manipulator dependencies and permissions were added; EAS ownership/project metadata was aligned to the current Fleet account.

Verification: Gemini unit tests pass, targeted lint has zero errors, the Next production build passes, and the Android Expo bundle exports successfully.

## What I learned

- A Gemini consumer subscription does not prove API availability; the API key and model endpoint must be exercised directly.
- `gemini-2.5-flash` was unavailable for this new API user, `gemini-3.7-flash` returned high-demand errors, and `gemini-3.6-flash` was too slow for the mobile timeout. `gemini-3.1-flash-lite` returned structured receipt data quickly enough.
- A camera guide only earns its place when the captured image is cropped to that exact visible region.
- GPS tracks trip distance, but a fuel record should not trust OCR or driver input for odometer. The server-owned vehicle mileage is the safer current source.
- Analytics must show an honest empty state. Fabricated fallback charts make an unfinished dataset look like real fleet evidence.

## Problems encountered

- Receipt scans initially returned no useful fields because the scan path mixed upload, local OCR, and Gemini fallback behavior.
- Petron's split `Description / Qty / Price / Amount` layout and Skyewin's discounted `TOTAL INVOICE` were commonly misclassified.
- Gemini initially returned `400` because structured output used the wrong request field; the legacy GenerateContent endpoint requires `generationConfig.responseMimeType` and `responseSchema`.
- The app previously surfaced `Current location is unavailable` as an uncaught promise rejection.
- EAS authorization failed while the local app metadata referenced a project owned by a different account/team.

## Decisions made

- Use Gemini as the only receipt extraction engine; manual completion is the recovery path.
- Keep the Gemini key and image processing on the server, never in the mobile bundle.
- Store fuel brand only for station name.
- Derive fuel-log odometer server-side from the assigned vehicle and remove it from receipt extraction/UI.
- Make the navigation Scan control a true shortcut that opens the camera immediately.
- Preserve two separate Reports and Analytics pages; access remains role-aware.
- Never populate analytics with fake fallback metrics.
