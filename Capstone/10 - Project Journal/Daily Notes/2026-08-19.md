# 2026-08-19

## What I worked on

**Mobile — real per-leg km + odometer + background GPS tracking.**

Phase 1 — per-leg km via foreground GPS (`mobile/app/(app)/(tabs)/map.js`):
- Added `haversineKm()`, `MAX_SEGMENT_KM`, `MIN_MOVING_SEGMENT_KM` and a
  `distRef` accumulator replacing the old `recordedLeg1/2` state.
- The watcher accumulates km per leg (`leg1` = to pickup, `leg2` = to drop-off)
  based on `trip_status`, with a straddling-fix drop on leg change and a
  noise filter (jumps > 0.4 km / parked jitter).
- Complete flow now sums the legs for the odometer delta and sends
  `{ distance, start_odometer, end_odometer }`; `complete.js` shows the
  TO PICKUP / TO DROP-OFF breakdown.

Change 1 — start odometer capture: all 4 `/start` flows now send `{ odometer }`
(`map.js`, `trip/[id].js`, `(tabs)/index.js`, `(tabs)/vehicle.js`).

Change 2 — fresh mileage before complete: `map.js` re-fetches `/api/mobile/driver/trips`
before completing and uses the fresh `current_mileage` as the odometer base.

Phase 2 — background GPS tracking (new):
- Installed `expo-task-manager` (14.0.9).
- `app.json`: added `ACCESS_BACKGROUND_LOCATION` / `FOREGROUND_SERVICE` /
  `FOREGROUND_SERVICE_LOCATION` permissions + `expo-location` plugin flags
  (`isAndroidBackgroundLocationEnabled`, `isIosBackgroundLocationEnabled`,
  `locationAlwaysAndWhenInUsePermission`).
- New `mobile/lib/background-tracking.js`: headless task `fleetops-background-location`
  posts GPS and accumulates per-leg km into AsyncStorage; exports
  `start/stopBackgroundTracking`, `updateLegContext`, `mergeStoredKm`, `legForStatus`.
- Wired `map.js` via `AppState`: background + active trip → start task;
  foreground → stop + merge km (clearing `prev` synchronously to avoid double-count).
- Ran `expo prebuild --clean` — `android/` regenerated with the background-location
  config; manifest confirmed to carry the permissions.
- ESLint: `background-tracking.js` zero errors; `map.js` no new errors.
- `expo config --type introspect`: UIBackgroundModes `location`, iOS Always
  permission, and all Android permissions resolve.

Superseded [[ADR-010 Foreground Only GPS]] with new [[ADR-011 Background GPS Tracking]].

- LaunchScreen polish: the location-beacon Lottie (`PRt4x4Ds0p.json`) has a fixed
  `#285448` fill — invisible in dark mode (same color as the dark `primaryContainer`
  gradient). Added `colorFilters={[{ keypath: "Location", color: colors.primary }]}`
  so it uses the theme `primary`: light → `#285448` (unchanged), dark → `#A6C7B8`.
  The car animation was NOT recolored — it is a raster image layer (`ty:2`), which
  `colorFilters` cannot recolor; the photo reads fine on both modes.
