# 2026-08-25

## What I worked on

### Tesseract replaced by Gemini document extraction — uncommitted

All staff and driver document scanning now runs on **Gemini structured output** instead of Tesseract OCR + regex parsing. The pattern proven by the mobile fuel scanner (`src/lib/fuel/gemini-receipt.js`) was generalized into a shared module:

- New `src/lib/ai/gemini-document.js`: one request per scan to `gemini-3.1-flash-lite` (env `GEMINI_DOCUMENT_MODEL` overrides), JSON `responseSchema` per document type (`Driver_License`, `Driver_License_Back`, `OR_CR`, `Insurance`), strict normalizers (calendar-valid dates → `YYYY-MM-DD`, sex → M/F, year ≤ current+1, seating capacity 1–60, PH phone formats), and **null for every unreadable field** — never guessed. Same 12-second timeout and 404 model-retry chain as the fuel scanner.
- `/api/ai/scan-document` shrank from ~370 to ~90 lines: tesseract import, all four regex parsers, the legacy OpenAI-compatible vision fallback, and the obsolete `document_text` parameter are gone. Response shape stays backward-compatible (`extracted_data`, `lto_schedule`, `validation_issues`, plus new `scan_engine`/`model`; honest empty `confidence_scores` instead of the old hardcoded pseudo-values).
- `/api/driver/license-scan` keeps its fail-closed contract unchanged — no key fields → retake guidance, zero DB writes — so the Expo app needed no changes.
- Browser Tesseract blocks were removed from `drivers/new`, `drivers/[id]/edit`, and `fleet/vehicles/new`; those handlers now just POST the image URL and let the server extract.
- Deleted `src/lib/ai/license-ocr.js` and `verify_ocr_timing.js`; removed `tesseract.js` from dependencies and `allowScripts` (npm pruned 13 packages). No DB changes.

Verification: full vitest suite passes (34 files, 413 tests, including 11 new tests in `src/lib/ai/gemini-document.test.js` covering date formats, name/sex normalization, OR/CR model-vs-series, insurance policy fields, reject-guessing cases, and image/PDF data-URL decoding); targeted lint has zero errors; production build passes; live smoke test against `gemini-3.1-flash-lite` returned well-formed structured JSON in ~1.8 s.

### Toast Notification Contrast & Universal Background Compatibility Fix

- **Target:** `src/components/ui/toast.jsx`
- **Issue:** Toast containers used a semi-transparent gradient (`from-emerald-500/15 via-emerald-500/5 to-white/90`) without an opaque base. When a toast fired over a dark backdrop (e.g. modal overlay during registration renewal, dark cards, vehicle scans, or dark elements), the dark backdrop bled straight through the 85-95% transparent left half. In Light mode, this caused dark text (`#111827` and `#4b5563`) to render directly over a dark/black backdrop, making toast titles, messages, and close icons virtually invisible.
- **Fix:** 
  - Added a solid, crisp surface base (`bg-white dark:bg-zinc-900/98 backdrop-blur-2xl`) with multi-layered elevated drop shadows (`shadow-[0_12px_36px_-6px_... dark:shadow-[0_16px_40px_-8px_...]`).
  - Swapped the raw alpha gradient for a subtle ambient tint over the solid base so transparency bleed-through is eliminated.
  - Replaced theme-dependent ambiguous text colors with high-contrast, crystal-clear typography (`text-zinc-900 dark:text-zinc-100` for titles, `text-zinc-600 dark:text-zinc-300` for messages) guaranteeing WCAG AAA legibility regardless of what background or modal is behind it.
  - Enhanced close button contrast and tactile hover feedback.

### Fuel request review — three-value model + approval ladder (evening)

Adopted an external review of the fuel request flow. The core fix: **Minimum Safe Refill ≠ Recommended Refill ≠ Maximum Allowed Refill** are now separate, explainable numbers instead of one conflated "39 L recommended".

- `request-policy.js` now emits `minimum_safe_liters` (forecast consumption + reserve − current, floored at 0) alongside the existing 90% `target_liters`, which is repositioned as the *preferred* operating level (fewer refuel stops), not a requirement.
- Approval ladder in `PUT /api/fuel/requests`: below-minimum approvals are blocked without an override reason; exceeding the monthly allowance now warns and allows with a required reason instead of hard-blocking scheduled operations.
- Fuel variance detection: reported level vs. expected remaining (last report − completed-trip consumption since); gaps > 15% of tank store `fuel_variance` in the snapshot and surface a ⚠ badge in the review modal. Evidence photos deferred to phase 2.
- Review modal rebuilt as a six-tile panel: minimum safe / preferred target / tank space / monthly available / current fuel / 24h forecast — the manager sees the reasoning behind every number. Client validation mirrors the server ladder via a shared `requestReviewFacts()` helper.
- Verified `allocationUsage()` already deducts only *verified* liters and holds approved-unverified amounts as committed — the reviewer's "deduct actual verified liters" concern was already handled correctly; documented rather than changed.
- Zero-remaining hard block at request creation removed so overrun decisions land with the manager (RBAC-aligned).

Verification: vitest suite **429 tests / 35 files** green (11 fuel-policy tests incl. the reviewer's own example as a regression case), targeted eslint clean on all four touched files, production build passes. No DB migration needed — everything rides the existing `calculation_snapshot` JSONB.

### Fuel policy engine — auto-authorization + transaction validation (night)

Second external review round adopted; module reframed as **Fuel Planning, Authorization, Monitoring & Consumption Control** (four layers documented in [[Fuel]]).

- **Policy auto-authorization** (`evaluateFuelPolicy`): clean requests approve themselves at creation — `status='Approved'`, `approved_by=NULL`, `auto_authorized:true` in the snapshot, audit action `auto-authorize`. Strict server-only conditions: positive recommendation, no variance flag, no range warning, min ≤ reco, budget covers reco. Everything else stays Pending with machine-readable reasons. Drivers can never inject an amount — `requested_liters` is always the server's recommendation.
- **Impossible-quantity check**: submission rejects when claimed liters + estimated current level exceed the tank ("only ~X L of space left").
- **Fuel-type mismatch flag**: Gemini schema gained nullable `fuel_type` (synonym-normalized: Gasoline≈Petrol≈gas, "deisel" typo tolerated, junk → null); persisted to new `fuelrecords.receipt_fuel_type` (**migration 067**, applied via `db:up`, `schema.sql` refreshed + verified live via information_schema). Verification modal shows "receipt says X, vehicle uses Y ⚠" — flag-only, never blocking.
- **Budget tiers + rename**: allocation table now shows utilization bars (green <80%, amber ≥80% "Near budget limit", red >100% "Budget exceeded"); all copy renamed allowance/allocation → *monthly fuel budget*. Requests table gains a "Within policy" badge on auto-approved rows and "Authorized" column header.
- Deliberately rejected: fuel cards, driver-entered odometer at pump (server-owned mileage stays), rolling efficiency analytics (phase 2).

Verification: suite **438 tests / 35 files** green (7 new policy tests + 2 Gemini normalizer cases incl. mismatch synonyms), eslint clean across 8 touched files, production build passes, migration ledger 71/71 valid with `npm run db:check`.

## Lessons / notes

- The regex parsers encoded hard-won Philippine-document knowledge (model vs. series on OR/CR, emergency-block slicing on licence backs). Gemini's prompt now carries that knowledge as instructions — but real-license accuracy should be spot-checked before demo day, since the smoke test only proves API contract, not field accuracy.
- Every scan is now an API call (~2–12 s) where OCR was free and offline. Quota exhaustion degrades to manual entry rather than breakage.
- One earlier file write silently didn't persist; re-verifying writes against disk caught it. Always confirm, don't trust success messages.
