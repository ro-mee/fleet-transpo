# 2026-09-24

## What I worked on

Recurring mobile "Network request failed" — stale LAN IP again.

### Cause

`mobile/.env` (gitignored, local-only) still pointed at `http://192.168.0.200:3000`,
but the dev PC's current LAN IP is `192.168.0.198` (DHCP reassigned it).
The phone tried a dead address → timeout → `ApiError` status 0.

Verified from the PC:
- `http://192.168.0.200:3000` → operation timed out (stale, as expected)
- `http://192.168.0.198:3000` → server responds (Next dev listening on `::3000`, all interfaces)

### Fix

- `mobile/.env`: `EXPO_PUBLIC_API_URL=http://192.168.0.198:3000`
- No code change; nothing committed (file is gitignored per `mobile/.gitignore:37`).

### Still required on the device side (not done by the agent)

1. Phone and PC on the same Wi-Fi (Tenda `192.168.0.x`).
2. Restart Expo (`npx expo start`) so the new `EXPO_PUBLIC_API_URL` is re-inlined into the bundle.
3. `npm run dev` running at the repo root (already was).

### Standing pattern (see [[Mobile Architecture]] "Local API reachability")

`EXPO_PUBLIC_API_URL` is bundled at Expo startup, so every DHCP IP change
breaks the physical phone until `mobile/.env` is updated + Expo reloaded.
Long-term options if this keeps recurring: DHCP reservation for the dev PC,
or `npx expo start --tunnel` (works off-LAN, slower).
