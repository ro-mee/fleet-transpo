# Doc Rot: ERDs Missing Core Table

> **RESOLVED 2026-08-11** (roadmap Phase 3, item 13 — commit `a654018`).
> `docs/erd/` is deleted. `schema.sql`, generated by `npm run db:dump`, is the
> replacement — which is path 1 below, and it already existed.

## The problem — was CONFIRMED

**Every ERD in `docs/erd/` was unusable as documentation of the live schema.**

| File | Entities | Problem |
|---|---|---|
| `docs/erd/fleet-erd.mmd` | 40 | Includes **dropped** tables (`branches`, `tripcostanalysis`, `automation_*`, `fuelstations`, `permissions`, `offlinesync`) |
| `docs/erd/fleet-erd-updated.mmd` | 23 | Also includes dropped tables |
| `docs/erd/fleet-erd.mermaid.md` | — | Third copy, same pre-013 multi-branch schema |
| `docs/erd/sub-system-relationships.md` | — | Fourth; models `BRANCHES` and `PERMISSIONS` |

> **There were four stale files, not two.** This note and the roadmap both said
> two — neither had listed the directory. All four modelled the pre-013
> multi-branch schema and none mentioned `transportation_requests`.
> → [[Things I Should Not Forget]]

**Neither contains `transportation_requests` — the actual core table of the live system** (15 rows, the main line of the booking flow). Also missing from both: `reservation_events`, `driver_vehicle_assignments`, `uvvrp_violations`, `recommendation_snapshots`, `driver_consents`, `mobile_refresh_tokens`, `notification_preferences`, `locations`.

## Why it's dangerous

An ERD is the first thing anyone looks at to understand a database. Reading these teaches: *"this system is about branches and trip cost analysis"* — which is the opposite of the truth.

This is the single clearest example of [[Documentation Rot]]: the diagram was drawn early, never updated, and the repo kept two versions so even the "updated" one is stale in a different way.

## What was actually done

Deleted all four, rather than redrawing. `scripts/dump-schema.mjs` already
generates `schema.sql` from the live database on demand, which is path 1 with no
new tooling: 38 tables, 1 view, 77 foreign keys, 84 indexes, 11 functions, 16
triggers as of 2026-08-11. A generated artifact cannot rot silently the way a
hand-drawn diagram does — if it drifts, `npm run db:dump` produces a diff.

**The lesson is about the failure mode, not the diagrams.** Four copies existed
because each time the schema moved, someone drew a new one instead of deleting
the old — so the repo accumulated four wrong answers to the same question and no
way to tell which was least wrong. The reason it went unnoticed for ~30
migrations is that nothing ever reads an ERD in CI. → [[Documentation Rot]]

The hand-maintained conceptual view for study purposes stays in this vault at
[[ERD]], where it is explicitly a learning aid rather than a reference.
