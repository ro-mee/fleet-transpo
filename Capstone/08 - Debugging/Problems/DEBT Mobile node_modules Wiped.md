> **STATUS: RESOLVED 2026-09-10.** Reinstalled from the lock file. The bundler failure below it (stray `</ClayCard>` in uncommitted `fuel-report.js` WIP) is separate and still open.

**Update 2026-09-10 (later same day):** the stray `</ClayCard>` is GONE from the working tree — openers/closers now balance 6/6 and `npx expo export --platform android` succeeds from the dirty tree (1365 modules, 5.13 MB hbc, `Exported: dist`). ## Symptom — CONFIRMED

```bash
$ npx expo export --platform android
Android Bundling failed 21448ms node_modules\expo-router\entry.js (1 module)
ERROR  Error: Cannot find module '@babel/code-frame'
```

`mobile/node_modules` existed but contained **0 items** — the whole dependency tree was gone (likely a wiped/dehydrated folder; the repo lives under OneDrive, whose Files On-Demand is known to hollow out `node_modules`). Metro died on the first module because `@babel/core` itself was missing.

## The fix — CONFIRMED

```bash
cd mobile
npm ci --no-audit --no-fund   # clean install from mobile/package-lock.json; 817 packages
```

`npm ci` (not `npm install`) so the tree matches the lock file exactly. After reinstall, Babel runs again — the export got past module 1 to 1356 modules before stopping on the unrelated JSX issue below.

## What the run revealed — CONFIRMED

With Babel working, the export now fails on a **different, pre-existing** error in uncommitted working-tree WIP (not on branch `perf/quick-actions`, whose HEAD bundles clean at 1359 modules / 5.15 MB):

```
mobile\app\(app)\fuel-report.js: Expected corresponding JSX closing tag for <View>. (909:12)
> 909 |             </ClayCard>
```

Line 909 is a stray `</ClayCard>` from the in-progress Clay UI edits (openers at 754/778/890, closers at 774/884/899/909 — one closer too many). Fix belongs to whoever owns that WIP, not to this reinstall.

## How to prevent it

- Keep `node_modules` out of OneDrive sync (Files On-Demand dehydrates it) — or reinstall with `npm ci` whenever Metro fails on a `Cannot find module` inside `node_modules` itself.
- Treat "Cannot find module 'X'" where X lives under `node_modules/@babel` or `node_modules/expo` as a broken install first, a code bug second: `Get-ChildItem mobile/node_modules | Measure-Object` should never be 0.
